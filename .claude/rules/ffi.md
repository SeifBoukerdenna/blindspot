# FFI boundary rules

This is the only place in the project where a mistake is memory-unsafe rather than
merely wrong. Treat it accordingly.

- Every `unsafe` block gets a `// SAFETY:` comment stating the invariant that makes it
  sound. No exceptions, no "obviously fine".
- No panics may cross the boundary. Every `#[no_mangle] extern "C"` entry point wraps
  its body in `std::panic::catch_unwind` and returns an error code on unwind.
- No `unwrap()`, `expect()`, or indexing that can panic anywhere reachable from an
  entry point.
- Rust allocates, Rust frees. Every function that returns a pointer or an owned struct
  has a matching `bs_free_*`. Never hand Swift something it is expected to `free()`.
- Strings cross as `*const c_char` that Rust owns, or as pointer + length. Never assume
  NUL-termination on data coming back from Swift.
- `include/blindspot.h` is generated by cbindgen. Change `ffi.rs` and regenerate; never
  hand-edit the header.
- If you add or change an entry point, update the Swift side in the same change. A
  header and a caller that disagree will link fine and crash at runtime.
